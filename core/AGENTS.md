# {{WORKBENCH_NAME}} 工作台

接单先读现有的 `AGENTS.local.md`、目标仓自己的约定及对应的 `.workbench/repos/<repo>.md`（根仓为 `.workbench/root-repo.md`）。在工作台根把 `$PWD/.workbench/bin` 加入 PATH，即可使用 `forge`。

## 定位与授权

用 `forge instance list --json` 查当前实例的验证环境、交付终点、阶段和技能来源。使用技能前用 `forge instance show skill <id> --json` 读取有效版本；描述、正文和相对资源一起生效。实例扩展说明和技能只提供工作指引。对外写操作按用户授权及受控执行器的登记范围进行。

Git 命令用 `git -C <仓>` 或在指定工作树内执行。沿用指定分支，保留已有改动。共享工作树禁止 stash、checkout --、restore、reset、commit --amend、add -A 和 add .。提交前核对 status、逐文件暂存、带 pathspec 提交。核对已合分支和工作树的实际归属后再清理。

## 正式开发

一项正式需求或缺陷绑定一个任务账本和工作 thread；用 `forge ledger status` 核对既有任务，跨仓使用 attach。临时查数、日志与沟通直接处理。规格、附件和实例私有材料保留在实例范围。

需求用 grill 对齐可观察的承诺，feature 负责实施到交付。完整模式默认产出 SSOT、互相隔离派生的技术与测试规格、独立评审，操作者确认 SSOT 并授权开工后，派生规格独立评审通过且承诺与风险边界一致即可自动冻结。轻量模式须同时满足改动局部单纯、未触及核心不变量或关键契约、主干已有测试覆盖。轻量规格写出修改范围、已有覆盖及补充用例，经操作者确认后冻结。两档下游均执行独立实现和测试、评审、隔离验证及交付。

缺陷和报警用 bugfix，从问题所在环境的只读证据定性。需要改变权益、业务承诺或授权边界时，说明选项、损失及代价，请用户裁决。已冻结规格确需改变，经用户确认后 amend，按影响重新冻结、验证。冻结用例保留原始断言。

## 评审、验证与交付

review 根据固定变更范围给出独立报告。调用评审 CLI 前先执行 `forge ledger reviews <task-id>`，对照历史版本、范围与角色结果决定本次角色。verify 在目标 SHA 的隔离检出中运行项目选择的工具，从公开入口核对交付行为。报告记录实际输出、退出状态或持久化结果，并区分执行通过、仅编译、失败和未验证。ship 以实例终点和本次授权为准，默认完成 PR 合入 main 并核验远端回执。移交与批次按各自任务记录版本和见证。外部 PR 意见使用 pr-triage。

在执行不可逆动作前，核对精确资源、版本、具体动作及内容摘要。快轨可在规格冻结时先批准范围与终点。runbook 与快轨均需主会话整句人工批准，受授权会话、时效和外部状态约束。发生漂移时停止并保留已确认回执。凭据只在适用环境使用，日志仅呈现脱敏结果。最小权限、分支保护及所需 CI 检查由部署方实施。

## 委派

ready 生成现场摘要。按所需专长选 scanner 只读检索、analyst 只读分析、implementer 在授权工作区实施、reviewer 独立只读评审。任务书指明输入、权限、输出和完成条件；实例在 `.workbench/models.toml` 配置模型档位。
