# 验证待交付版本

**输入**为任务、目标仓和 SHA、验收标准、冻结用例及有效实例配置。

1. 用 `forge instance list --json` 查验证环境、手段和阶段，运行 `forge doctor . --json` 定位无效配置。明确本次验收覆盖的入口和失败行为。
2. 零覆写实例在固定 SHA 的干净隔离检出上使用仓库已声明的检查及测试脚本；JS/TS 使用 Bun。隔离运行不引入工作目录中的未提交内容或个人凭据。若必要命令缺失，报告缺少哪一项检查或输入。
3. 用 `forge verify --task "$TASK" --cwd "$CHECKOUT"` 记录目标版本的实际验证。显式指定验证阶段时，核对 `forge instance show stage <id> --json` 的有效动作及来源，由配置的执行路径运行。按契约使用独立测试、临时数据和端到端入口；编译成功仅证明可编译。
4. 复核结果及日志，清除本次创建的检出、服务与夹具；失败也须清理。修复后对新 SHA 重验。

**输出与完成条件**为绑定版本的静态、执行及集成结果、退出状态和夹具清理结果。缺权限、缺外部服务、执行失败和仅编译分别注明。全部必需验收均有通过证据后交给 ship。
