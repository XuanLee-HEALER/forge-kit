# bugfix：修 bug

遵守工作台根 `AGENTS.md` 与目标仓 `.workbench/repos/<repo>.md`。

## 步骤

1. **定终点与深度**：先确定本次交付终点（默认 `local`）与验证深度（`targeted` / `full`）。
2. **定位根因与证据**：线上问题基于 prod 真实数据查证（不拿测试环境推断）；第三方库行为先查源码或官方文档。
3. **确认修复范围**：向用户汇报根因、证据、拟改仓库与行为变化边界，停下等明确确认；除非用户已一次性授权直接修复。
4. **分支与开账**：复用已有分支/worktree，需要新建时从 `origin/main` 切出。用 `.workbench/bin/ledger open` 建立本次缺陷账本（跨仓用 `ledger attach`）；不涉及逻辑/设定的极小改动可按规则使用 `ledger exempt`。
5. **修复与回归**：优先委派 `.codex/agents/dev.toml` 实现修复并补最小反例回归测试（小改动可直接处理）。涉及接口语义变化时同步接口注释、文档与生成产物；发现需扩大修复范围时回到第 3 步确认。
6. **验证与收尾**：运行受影响构建、测试与回归，按风险执行 `wrapup`；`local` 终点直接汇报，`fat` / `pr` / `prod` 按 `ship` 推进（生产修 bug 默认打 hotfix tag）。任务完成后 `ledger close`。
7. **汇报**：根因与证据、实际改动、分开列示单测与环境验收、当前终点与剩余缺口。
