# 工程风险标尺

依据真实用法判断触发频次。L1 是预期操作或常见失败，L2 是连点、切 Tab 返回等自然误操作，L3 是刻意构造或罕见条件重合。

## 红线

1. 违反已确认的 `INV-*` 或冻结契约。
2. 资金、计费、配额或权益错误。
3. 权限越界或泄密。
4. 持久化脏写或静默丢失。
5. 核心流程不可自愈或大量工作成果丢失。

## 处置

- **Must-Fix** 适用于命中任一红线或存在 L1 真实缺陷的情况。红线由主线程修复或取得操作者明确裁决。改变冻结承诺须经确认并执行 `forge ledger amend`。
- **Cheap-Fix** 适用于其余成立项中损失轻微、局部低成本即可修复且无需新状态或耦合的问题。
- **可接受风险** 适用于损失轻微的 L3 或可一次重试并保住用户成果的轻微 L2，且修复需新增状态、锁或跨代兼容层。说明接受的边界与重议条件。
- **证据缺口** 单列无法确认的事实及缺少的材料。关键证据缺失时使用 `incomplete`。

评审将 Must-Fix 列为阻断，将 Cheap-Fix 与可接受风险列为建议。每项判断注明频次及依据、实际损失、恢复成本和修复复杂度。阻断注明命中的红线或 L1 路径，以及触发条件、可观察后果与可定位证据。接受风险也须举证，包括成果如何保留及修复为何需要额外复杂度。

| 情境 | 判断 |
|---|---|
| 关闭动画里再次点击，仅多一次只读请求，成果保留，修复要加锁和定时清理 | 可接受风险 |
| 罕见的旧数据漏填可选备注，局部补一个可选链即可恢复展示 | Cheap-Fix |
| 校验失败后按钮锁死，刷新会丢失已填长表单 | Must-Fix |
| 重复提交会重复扣费 | Must-Fix |
