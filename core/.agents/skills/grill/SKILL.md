# 需求定稿

**输入**为原始需求、已有承诺、目标仓及可查证的外部行为。产物写到实例的 `.workbench/specs/<task-id>/`。

1. 检查真实入口、历史数据及调用方，确认受影响的人、触发条件与可观察结果。对多种合理解释，说明适用场景、发生频率、用户损失、恢复成本和实现代价。能由既有证据回答的问题自行解决。
2. 把会改变业务承诺、权限、验收边界或可接受损失的取舍提交用户裁决。记录已确认的决定以及何种新事实需要重议。
3. 完整模式写 `ssot.md`，列目标、编号不变量、正常及异常流程、外部契约、存量兼容和验收边界。字段、状态、失败行为与交付结果须可独立验证。轻量模式按 feature 的三个准入条件写 `scope.md`，列修改范围、主干覆盖依据及补充测试用例。

**输出与完成条件**为用户明确确认的规格及决定。完整模式取得操作者确认 SSOT 和开工授权后，将同一份 SSOT 交给独立的方案作者和用例作者；轻量模式由 feature 核对确认并冻结。
