# 运行时排查

1. 确认排查对象、目标环境和时间窗。环境未指明时先询问操作者；同一结论使用同一环境的证据，全程只读。
2. 先运行 `forge rt list --json`，核对可用原语、绑定和只读保障级别（read_only_guarantee）。对 unverified 绑定，在发送前确认查询本身只读。针对一个可证伪的假设，说明什么观测会推翻它，然后按需用 status 查运行版本、changes 对照变更、metrics 查指标、logs 或 query 核实异常。对照运行版本对应的代码，记录环境、时间窗及可复核的脱敏结果。
3. 按「现象 / 可复核证据 / 判定 / 影响面 / 下一步建议」报告。判定取「数据问题」「配置问题」「代码 bug」「证据不足」之一。缺少支持结论的实证时选择「证据不足」，列出需要补取的事实。
4. 确认代码 bug 时携带完整根因、版本和证据转入 bugfix 账本。需要向线上写入数据、更改配置或重启服务时交还操作人或转入 ship 审批。
