# 需求与问题分析

按 `AGENTS.md` 的「需求与问题判断」四条原则给出结论；只深挖会改变选择的事实。

- **谁会遇到什么？** 从真实入口说起，交代触发条件、用户看到的结果、损失与恢复方式；入口与受理状态先由负责人自行查证。
- **哪条业务承诺受到影响？** 对照用户已确认的取舍与本次目标；若建议新增承诺，明确写清受益方与代价。
- **做到哪里就够了？** 对比保持现状、最小修正与完整方案，权衡业务收益、用户恢复代价与维护成本；根因相同的多条评审意见只做一次裁决。
- **用户需要决定什么？** 用两三句话交代场景、推荐处置与具体代价；现有承诺已足以裁决时直接给结论，不把机械判断甩给用户。把裁决结果写入任务账本（`ledger decide`）。

## 通用判断示例

同一界面现象（如“断网后按钮一直锁着”）不能直接决定是否修复：先查请求是否已发出。若请求已发、受理未知，按既有取舍保留锁防重复扣费/提交可放过；若在本地校验阶段即失败却永久锁按钮，则属阻断核心流程的真缺陷，应在授权范围内修复。
