# form-ux：表单布局与交互规范

适用于各仓库的新建、修改、修复与评审表单任务（用户明确要求优先；UI 技术栈、共享组件与主题遵循目标仓 UI 规范）。改动限于当前表单及必要调用链，不顺带重做历史表单；不授予网页/浏览器自动化测试权限。

## 开发前核对

从需求、契约与实现核对每个字段：类型、必填、上下界、精度、单位、默认值、空值含义、联动约束及新建/编辑差异；不凭通用组件默认范围推断业务限制。

## 布局与控件

- 按业务关联分组并保持自然填写顺序；相关短字段可并排，长文本/描述/提示词独占一行；窄容器自然换行且视觉顺序与 Tab 顺序一致。
- 每个字段保留可见标签（placeholder 不替代标签）；必填标 `*` 并提供可访问必填语义（星号不是校验实现）；关键单位/范围/空值含义就近说明，不藏在 tooltip。
- 少量选项直接展示，大量选项用搜索选择；不虚构业务默认值应付校验。

## 校验时机与错误反馈

- 新建表单首次打开不将所有未填项立即标红；修改后的必填空值/纯空白与明确越界即时反馈，修正后立即消除错误。
- 邮箱、日期等输入中不完整内容通常失焦校验，不打断中文输入法（IME）组合输入。
- 提交时统一校验所有适用字段；失败保留输入并定位聚焦首个错误。错误用红框+具体可操作文字呈现，字段错误与网络/系统错误分离；前端校验不替代后端校验。

## 数值输入与选项联动

- 即时校验、提交校验与实际传值使用同一边界（`0` 不误判为空）；默认保留非法输入供用户修正，不在失焦时静默夹取或重置；不因回写丢焦点/光标/小数点。
- 默认值必属候选集合；候选失效明确提示重选，不静默替选第一项；隐藏条件字段明确是否清空/提交/参与校验；动态列表保持稳定 key 不串值。

## 保存、键盘与验证

- 通常允许点击保存以暴露错误，请求中防重复提交；保存失败保留输入并支持修正重试；关闭有未保存改动的表单遵循既有保护。
- 回车提交遵循表单语义且不误触多行输入或 IME 确认；弹窗的焦点进入、约束与关闭后焦点返回遵循仓内现有能力；错误通过 `aria-invalid` / `aria-describedby` 关联。
- 修改共享输入/表单组件时须核对其他调用方，局部新行为通过显式参数启用，不顺带改变其他表单。
- 涉及即时校验与联动时，使用仓库模拟 DOM 组件交互测试覆盖输入、清空、越界、失焦、修正、提交与回填（不替代也不触发未授权的浏览器自动化测试）。
