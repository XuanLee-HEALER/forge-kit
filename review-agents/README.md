# review-agents

Run a fixed-commit review from a Bun workspace or its standalone distribution.

```sh
review-agents/bin/review --repo ./project --base "$BASE" --head "$HEAD" --spec ./requirements.md --roles business,quality --mode ordered --order quality,business
```

The default runs business, quality, simplify (including performance), and comments in parallel. Serial mode uses the listed role order. Ordered mode requires an exact permutation of the requested roles. Every role starts with the same pinned materials; business also requires a readable specification. Both backends receive identical repository data. For up to eight changed source files the engine selects relative module dependencies and searches the pinned head for callers of changed declarations. It attaches numbered snippets from up to twelve unchanged source files (4 KiB each), excluding private workspace data and instruction files. The engine limits each changed blob and the combined numbered diff to 1,500,000 bytes. If material cannot fit, it stops opening subsequent diffs and lists unread paths in the incomplete result. Private or binary material also yields an incomplete result. The report includes every selected role. An empty `attempts` array means that no backend started for that role. Forge records these unstarted selections as `review_selection` with `missing_materials`. The review history lists them alongside executed `review` records. Delivery waits for a successful execution of the same role and range. Model reports identify blocking findings and suggestions on changed paths. Each role returns its validated `limitations` alongside the findings. Forge retains these limitations in review evidence and displays them in `forge ledger reviews <task-id>`.

Auto starts a fresh ephemeral read-only Codex CLI for each role. A recognized provider outage or quota failure allows a single API attempt. Explicit `--backend codex` and `--backend api` select one backend. The Codex executable comes from PATH or `FORGE_CODEX_BIN`. The API expects `OPENAI_API_KEY` or a private TOML file at `REVIEW_CONFIG` (default `~/.config/review-agents/config.toml`) with `openai.api_key`. A compatible Responses endpoint can be configured with `OPENAI_BASE_URL`. Use `--model` and `--effort` to select the runtime model. Exit codes are 0 for pass, 1 for blocked, 2 for execution error and 3 for incomplete.

From this directory run `bun run check`, `bun run build`, and `bun test tests`. Run `bun run eval` to score four labeled defects and their clean controls through the Codex subprocess adapter and a loopback Responses API. Offline results use deterministic simulated providers. Run `bun run eval --live` to score the same inputs with real models. Each returned record includes the exact material revision, role, actual provider, result, and score.
